# しっぽ帳 GitHubの使い方と設計

版: v0.2（2026-10-07）。ユキさんの決定（Public、英数字のファイル名、GitHubへの書き込みはユキさんの許可を得てから）を反映。以前: v0.1で新規作成

## 1. 何が変わるか
- 置き場が1か所になる。最新のファイルは、いつでもGitHubにある。保管庫への手作業での入れ替え、古いファイルの削除、版付きファイル名の管理が、いらなくなる。
- ファイルの作成・更新は、これまでどおりクロが行う。GitHubへの書き込みは、ユキさんの許可を得てから行う。ユキさんは、更新のたびに保管庫を触らない。
- 版の履歴は、GitHubが自動で残す。前の版を見たり、戻したりできる。ファイル名に版を入れる必要はない（版は、ファイル冒頭の「版:」の行に残す）。
- アイさんは、GitHubのファイルのURLを読む（書き込みはできない）。ファイルの添付が、いらなくなる可能性がある。ただし、無料版のアイさんが、GitHubのURLを読めるかは、確認していない（手順5で確認する）。

## 2. ユキさんの作業（最初の1回だけ）
1. GitHubのアカウントを作る（無料）。github.com で「Sign up」。
2. リポジトリ（置き場）を作る。右上の「＋」→「New repository」。名前は shippo-cho。公開範囲は、「Public」を推奨（理由は5）。「Add a README file」は付けない（READMEは、クロが入れる）。
3. claude.ai の設定で、GitHubを接続する（設定のコネクタなどの項目。表示は変わることがあるので、迷ったら画面の写真を送ってください）。接続のとき、shippo-cho へのアクセスを許可する。
4. クロに、「ユーザー名/shippo-cho」を伝える。クロが、リポジトリに接続して、ファイル一式を書き込む。
5. アイさんで確認する。GitHubでREADME.mdを開き、「Raw」ボタンを押して、そのURLをコピーする。アイさんに「このURLを開いて、内容を読めるか」と聞いて、結果を教える。読めれば、アイさんは今後このURLから読める。読めなければ、読める形（案: 動物ごとの小さなファイルに分割）を、クロが用意する。

作業は、手順1〜5で全部。ファイルの移動やアップロードは、クロが行う（クロがGitHubに書き込めない場合の代わりの方法は、7）。

## 3. 日常の運用（誰が何をするか）
| 場面 | ユキさん | クロ | アイさん |
|---|---|---|---|
| ファイルの更新 | チャットで修正点を伝える（今までどおり）。出来上がりを確認して、GitHubへの書き込みを許可する | 反映してファイルを作り、ユキさんに見せる。許可を得てから、GitHubに書き込む。「何を、なぜ」を、コミットのメッセージに残す | 読むだけ |
| 内容の確認 | GitHub上で、整形された表示で読める。チャットで、クロに送らせてもよい | 必要なら、ファイルをチャットに送る | — |
| 仮想実例・検証中のもの | 事例、回答、想定ポイントを、クロとアイさんに手で渡す（今までどおり） | 事例に回答する。完了した事例は、許可を得て verification/cases に記録する | 事例を作り、回答する（チャット経由） |
| 版の確認 | READMEの表、またはファイル冒頭の「版:」で確認 | READMEの表と、ファイル冒頭の版を、同時に上げる | — |
| 前の版に戻したい | クロに伝える | GitHubの履歴から戻す | — |

ユキさんのコメントは、断りがなければ07（判断原理）・02などに反映する、という10のルールは、そのまま続ける。

ユキさんの決定（2026-10-07）: GitHubに入れられないもの（検証中の事例、アイさんが読めないものなど）は、これまでどおり、ユキさんがクロやアイさんに渡す。GitHubに入れるのは、確認が済んだ参照資料と、完了した記録だけ。

## 4. ファイル設計
いまのファイルを、内容を変えずに、フォルダに整理して移す。

```
shippo-cho/
├ README.md                         ← しっぽリードミー（読み方ガイド、ファイル一覧、運用ルール）
├ data/                             ← 参照資料（一次データと判断原理）
│  ├ 00_cross_comparison.md          （旧 00_横断比較表）
│  ├ 01_dogs.md                      （旧 01_犬（代表犬種））
│  ├ 02_cats.md                      （旧 02_猫（代表猫種））
│  ├ 03_birds.md                     （旧 03_鳥）
│  ├ 04_hamster.md                   （旧 04_ハムスター）
│  ├ 04_guinea_pig.md                （旧 04_モルモット）
│  ├ 05_housing.md                   （旧 05_飼育環境・住環境）
│  ├ 06_owner.md                     （旧 06_飼い主側の要因）
│  ├ 07_principles.md                （旧 07_判断原理）
│  ├ 08_unverified.md                （旧 08_未検証・要確認事項）
│  └ 09_rescue_congenital.md         （旧 09_保護犬猫と先天性疾患）
├ verification/                     ← 仮想実例の検証
│  ├ 10_verification_spec.md         （旧 10_仮想実例の検証仕様）
│  ├ 11_verification_log.md          （旧 11_検証記録）

│     └ case01_cat_couple60s.md      （旧 事例1_検証記録。完了した事例だけ置く）
└ docs/

```
- 中身は変えていない。変えたのは、ファイルの置き場所とファイル名、READMEの表と運用ルール、11の事例の記録の場所（11 v0.6）、10の追記（10 v0.4）。
- ファイル名を英数字にした理由: 日本語や括弧の入ったURLは、アイさんのような他のAIが読むときに、読み込みに失敗することがあるため。日本語の名前は、READMEの表の「旧」に残した。ファイルの中身（見出し・本文）は、すべて日本語のまま。
- 版は、ファイル冒頭の「版:」の行で管理する（これまでと同じ）。ファイル名には入れない。
- 事例2は、進行中（アイさんの想定ポイントとユキさんの評価が未了）なので、移行に含めない。完了したら cases に置く。

## 5. 公開範囲（Public／Private）の考え方
- Public（誰でも読める）【ユキさんが選択、2026-10-07】: アイさんが、ログインなしでURLから読める。クロも読める。推奨。ただし、中身は誰でも見られる。中身は、出典付きの要点、ユキさんの経験則（Cの記述）、検証の記録。メールアドレスなどの個人情報は含めていない。ユキさんが公開してよい内容か、確認してほしい。
- Private（自分だけ）: 内容は守られるが、無料版のアイさんは、おそらく読めない。
- あとから、Public／Privateを切り替えることはできる。まずPublicで始めて、アイさんで試す、という進め方もできる。
- 出典の記述は、要点を自分の言葉で書き直したもの（原文の写しではない）。出典のURLは、各ファイルにある。
- 検証中の事例（想定ポイントや相手の回答）は、リポジトリに置かない。アイさんがリポジトリを読めると、想定ポイントや回答が見えてしまい、独立回答が崩れるため。

## 6. 長いファイルについて（第2段階の提案）
- 無料版のアイさんは、長いファイルを一度に読めない。いまのファイルは、01_dogs が約76KB、02_cats が約54KB、06_owner が約33KB、09_rescue_congenital が約37KB と長い。GitHubに置いても、1ファイルの長さは変わらない。
- 対策案: 動物ごと・犬種ごとの小さなファイルに分割する（例: data/dogs/shiba.md）。READMEに、どのファイルを読めばよいかの案内を付ける。分割は、クロがスクリプトで機械的にできる。
- 今回は、「いまのものをそのまま移す」を優先する（ユキさんの希望）。分割は、アイさんの読み込みの結果（手順5）を見て、必要なら次の段階で行う。

## 7. 代わりの方法（クロがGitHubに書き込めないとき）
- GitHub上のブラウザの画面で、「Add file」→「Upload files」から、ファイルをアップロードできる。クロが用意した一式を、ユキさんが、フォルダごとドラッグする。
- ただし、手作業の入れ替えが戻るので、最後の手段。まず手順3の接続を試す。

## 8. 保管庫（claude.ai のプロジェクト）の扱い
- 移行後は、保管庫のファイルを更新しない。古いまま残ると、混乱のもとになる。
- 案: 保管庫には、READMEだけ（「最新はGitHubにある」と書いたもの）を置き、データのファイルは外す。または、保管庫にGitHubを連携できるかを、確認する（できるかは、まだ確認していない）。
- どうするかは、移行が終わってから決める。

## 9. まだ確認できていないこと
- 無料版のアイさんが、GitHubのファイルのURLを読めるか（手順5で確認する）。
- クロが、GitHubに書き込める状態になるか。いまは、GitHubのアカウントが接続されていない（確認済み）。手順3のあとに、確認する。
- 保管庫（プロジェクト）に、GitHubを連携できるか。
- 画面の表記や、設定の場所は、変わることがある。迷ったら、画面の写真を送ってください。

## 10. 決定事項と、残っていること
- 決定（2026-10-07、ユキさん）: 公開範囲はPublic。ファイル名は英数字（日本語名はREADMEの表に残す）。GitHubへの書き込みは、ユキさんの許可を得てから行う。
- 残り: 保管庫の扱い（上の8）は、移行が終わってから相談する。
