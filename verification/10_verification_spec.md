## 1. 目的
- 一次データベースと判断原理が、実際の飼育相談に近い仮想事例に対して、適切な推論・助言を生成できるかを検証する。
- 今回の段階では、知識データを大量に追加することは目的としない。基本データと判断原理から、AIが個別事例をどう推論するかを確認することが主目的。

## 2. 参加者と役割（修正）
- ユキさん: 仮想実例の回答者ではない。クロとアイが作った事例と回答、および出題者のコメントに、実務経験に基づくコメントをつける（妥当性、必要な修正・指摘、一般化できる判断原理の抽出）。各事例の模範解答は原則として作らない。評価の結果は 11_検証記録 に残す。事例を相手に渡す作業（コピーして貼る）も、ユキさんが行う。
- クロさん（Claude）: 開発・検証側。仮想実例を作り、アイの事例に回答する。相手の回答にコメントする。最後に、全員のコメントをまとめてファイルに反映する。使うもの: 一次データベース、07_判断原理、必要に応じて他のしっぽ帳資料。原則として、現在のデータベースと判断原理から推論する。
- アイさん（ChatGPT）: クロとは独立した立場。仮想実例を作り、クロの事例に回答する。相手の回答にコメントする。前提は、事例条件、しっぽ帳の共通データベース、判断原理。
- ジミーさん: GitHubのファイルを直接読めない（ユキさんの確認、2026-10-07）。検証やそのための資料作成に加わる場合は、必要なファイルをユキさんが直接貼り付けて見てもらう。
- 回答者は、自分が回答する事例について、相手の回答や出題者の回答を見ずに回答する。

## 3. 基本方式（修正: 互いの事例に回答し、コメントを重ねる）
「出題（交代制）→ 相手が回答 → 出題者がコメント → ユキさんがコメント → 必要時のみ指摘 → クロが反映」
1. クロとアイが交代で仮想実例を作る。作るのは問題（事例）だけ。今のひな形に従う。出題者の「想定ポイント」は書かない（推測できるため。2026-10-07）。
2. ユキさんが事例をコピーして、相手に渡す。相手が回答する。回答は、他方の回答を見ずに書く。
3. 回答が返ってきたら、出題者（回答者の相手）が、その回答にコメントする。
4. 次に、ユキさんが、回答と出題者のコメントのそれぞれにコメントをつける。
5. ユキさんのコメントに対して、クロ・アイが意見を述べるのは、次の場合だけ。
   - ユキさんのコメントが、過去の条件（これまでに決まったこと、事例の条件）と矛盾する場合。
   - 多くの資料（一次データ、判断原理など）に書かれている内容と、明らかに違う場合。
   - 他の資料に出ていない、というだけの意見は入れない。ユキさんのコメントは、経験則（C）として扱う（反映のルール参照）。
6. クロが、事例・回答・各コメントをまとめて、ファイルに反映する（07・02などの更新、11_検証記録への記録）。一般化できる問題があれば、修正候補とする。ただし、クロとアイの意見がずれた場合は、1件では変更しない（11参照）。
7. 次の事例へ進む。
- 必要なら、同じ事例に、出題者も別に回答して比較する。最初は行わない。

## 4. 独立の保ち方（修正）
- 回答者は、他方の回答を見ずに回答する。出題者のコメントや、ユキさんのコメントも、自分の回答を書き終えるまでは見ない。
- コメントの段階（3〜5）では、回答・コメントを互いに見てよい。
- 確認すること: 出題者のコメントと回答が一致した点／異なった点／回答者だけが見つけたリスク／出題者も回答者も見落とした点（ユキさんが指摘）。

## 5. 仮想実例の作成
実際の飼育相談としてありそうな条件で作る。すべての条件を毎回入れる必要はない。
- 飼い主側: 年齢、家族構成、生活時間、在宅／外出状況、住居、住居規約、将来的な生活変化、飼育経験、動物に求めるもの、健康・身体能力など飼育に影響する条件。
- 動物側: 種、犬種・猫種など、年齢、性格・行動特性、必要な運動・交流、医療上の特徴、飼育環境への要求。
- その他: 留守番、旅行、家族の協力、近隣環境、将来的な不確定要素。
- 予算は事例に入れない（修正）。ただし、大型犬など、動物側の特性として費用がかかる、という記載は助言に入れてよい（金額は扱わない。07 P8）。

## 6. 回答に求める内容
- 単純な「おすすめ／おすすめしない」の二択にしない。原則として次を検討する。
  1. 事例の重要な条件
  2. 動物側の特性との適合・不適合
  3. 主要なリスク
  4. リスクを緩和できる要素
  5. 飼育する場合の具体的な注意点
  6. 条件を変更できる場合の代替案
  7. 追加で確認すべき情報
  8. 現時点での総合的な助言
- 「この条件なら○○を選ぶ方がよい」ではなく、「○○という条件が解決できるなら選択肢になる。難しい場合は△△を検討する」の形を取る。

## 7. 判断原理との対応
- なぜその判断になったのかが追跡できるようにする。確認する項目: 種・品種固有の特性、個体差、飼育環境、飼い主側の条件、将来変化、リスクを緩和する要素、判断原理。
- 結論が、知識の検索なのか、判断原理を使った推論なのかを区別する。

## 8. コメントの段階で確認する事項
- A 一致: 出題者のコメントと回答が合った部分。判断原理・データベースが機能している可能性が高い。
- B 相違: コメントと回答が異なる部分。原因を次のどれかで検討する: 使った知識の違い／判断原理の解釈の違い／条件の重み付けの違い／情報不足／推論上の誤り。
- C 回答者だけが指摘した事項（またはコメントにだけあって回答にない事項）: 重要なリスクや選択肢の妥当性を検討する。
- D 出題者も回答者も見落とした事項: ユキさんのコメントで新たな重要事項が見つかった場合、個別事例に限られるのか、一般的な判断原理として追加すべきかを検討する。

## 9. 判断原理へのフィードバック
- 仮想実例の結果を、そのまま事例集として蓄積することは目的としない。
- 修正の対象は、他の事例にも適用できる、一般化可能な知見とする。
- 例（良くない形）: 「60代夫婦で犬を飼う場合、このケースでは○○犬が良い」。
- 例（良い形）: 「将来の飼い主の身体能力低下が予想される場合、現在の運動要求だけでなく、将来の運動管理能力も評価する」。

## 10. データベースへのフィードバック区分
1. 判断原理の追加・修正: 一般化可能な判断方法が見つかった場合。
2. 一次データの修正: 既存データの誤り・不足・信頼性の問題が見つかった場合。
3. 未検証事項への追加: 重要だが、現時点では根拠が不足している場合。
4. 個別事例のみ: そのケースでは有効だが、一般化できない場合。原則として判断原理には追加しない。

## 11. 判断原理を安易に変更しない
- 仮想実例1件の結果だけで、すぐに判断原理を変更しない。（ユキさん確認: どうしても困ることがあれば見直す）
- 同様の問題が複数の事例で起きる場合、または明確な根拠がある場合に、修正を検討する。
- 目的は、個別事例に合わせて判断原理を変えることではなく、判断原理が多様な事例に対して機能するかを検証すること。

## 12. 事例の難易度
- Phase 1 基本事例: 単一の動物種、比較的単純な条件。例: 一般的な犬・猫の飼育相談、小鳥、ハムスターなど。
- Phase 2 複合条件: 複数の制約があるケース。例: マンション＋留守番、高齢化＋大型犬、共働き＋子犬、アレルギー＋動物種選択。
- Phase 3 難しい判断: 本人の希望と飼育条件が衝突するケース。例: 「どうしてもこの犬種を飼いたいが、現在の生活条件に明確な問題がある」。単純に否定しない、希望を尊重する、リスクを明示する、条件改善や代替案を示す、という判断原理が機能するかを確認する。
- Phase 4 将来変化: 高齢化、転居、仕事の変化、家族構成の変化、飼い主が先に亡くなる可能性など、時間軸を含むケース。
- Phase 5 特殊・境界事例: 判断原理の限界を探るケース。

## 13. 検証の最終目的
- クロとアイが同じ答えを出すことではない。
- 同じ基本データと判断原理から、それぞれが妥当な推論を行い、相違が生じた場合にはその理由を説明できること。
- 仮想実例を重ねることで、判断原理そのものの不足・矛盾・盲点を発見すること。

## 14. 最初の実施方法（修正）
- まず数件の基本事例（Phase 1）を実施する。目的は、この検証の進め方（事例の作成 → 回答 → 評価 → 記録）が回るかどうかの確認。
- 最初の数件では、知識を追加しない。「現在のしっぽ帳がどのような推論をするのかを観察する」ことを優先する。
- （2026-10-07、ユキさん）進め方が回ることを確認できたので、事例は10〜20件まで続ける。事例を重ねて、参照データを整える。あわせて、検索の範囲を広げ、[D]（未検証）も載せて、ユキさんが真偽を指摘する（07 P6）。
- 知識の追加（05・06の作成を含む）は、その後の段階で行う（ユキさん確認）。その結果を見て、以後の事例の難易度・種類を調整する。

## 15. 重要な設計思想
- 「正解を覚えているAI」を作ることが目的ではない。
- 目標は、基本的な動物知識と、一般化された判断原理から、個別の飼育相談について妥当な選択肢を推論できるAI。
- 仮想実例は、正解を教えるための教材ではなく、判断能力を検証するためのテストケースとして扱う。

## 事例のひな形（クロが決定。不都合があれば修正）
作成者は、次の形で事例（問題）だけを書く。想定ポイントは書かない。
- 事例番号・作成者・段階（Phase）
- 相談者（年齢、家族、住まい、住居規約、生活時間、飼育経験、健康・身体、将来の見込み、希望する動物と理由）
- 相談の内容（相談者の言葉で、3〜6行）

## 回答の書式（クロが決定。不都合があれば修正）
回答者は、次の見出しで書く。1事例あたり、読みやすい長さ（目安は1,500〜2,500字）。
目安を超えて長くなった場合は、1,500〜2,500字の要約版を回答として記録に載せ、元の詳細版は別ファイル（事例○_クロ回答_詳細版.md など）に残す。要約版は詳細版を縮めたもので、新しい内容は加えない。内容に違いがあれば詳細版を正とする（2026-10-07、ユキさんの指示）。
1. 重要な条件（事例から読み取れる、判断に効く条件）
2. 適合・不適合（動物側の特性との関係）
3. 主要なリスクと、緩和できる要素
4. 具体的な注意点
5. 条件を変えられる場合の代替案（他の動物種・犬種・猫種は「可能性」として）
6. 追加で確認したい情報
7. 現時点の総合的なアドバイス（「判定」ではなく「アドバイス」の形）
8. 判断の根拠（使ったデータ・使った判断原理の番号）

## 反映のルール（ユキさん、2026-10-07）

- クロとアイの意見がずれる場合は、数回の事例を見て、同様のずれが続くなら修正する（1件では変更しない。10の11と同じ考え方）。
- ユキさんのコメントに対するクロ・アイの意見は、過去の条件との矛盾、または多くの資料に書かれた内容との明らかな違いがある場合だけ指摘する。他の資料に出ていない、というだけの意見は反映しない（ユキさん、2026-10-07）。
